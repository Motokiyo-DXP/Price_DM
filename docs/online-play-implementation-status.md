# オンライン対戦 実装状況と作業順

更新日: 2026-09-03

## 実装方針

オンライン対戦は、後工程の作り直しを避けるため、次の依存順で進める。

1. サーバーを唯一の正しい盤面とし、更新番号と競合解決をサーバーで管理する。
2. 非公開情報を閲覧者ごとに整形し、テーブルや Realtime から盤面全体を直接配信しない。
3. シャッフル、山札参照、初期盤面生成をサーバーへ移す。
4. ルーム、準備、開始、切断、終了、再戦、清掃の状態遷移を完成させる。
5. 通知、確認、警告、相手操作表示など、一時的な Realtime UI を接続する。
6. SQL スモークテスト、単体テスト、型検査、ビルド、ローカルブラウザを連続実行する。
7. 最後にだけ、2アカウント・2端末での実操作確認を行う。

## 2アカウント相当の自動E2E

実在する40枚デッキを使い、私設ルーム作成、合言葉参加、host/guest着席、双方準備完了、サーバー初期盤面生成、ランダム先攻、投了、双方の再戦合意までを、異なる2ユーザーとしてリンク済みDB上で連続検証済み。テストはトランザクション内で実行し、終了時に全データをロールバックする。

残る必須工程は、異なる2アカウント・2ブラウザまたは2端末による実UI操作確認のみ。使用量50%警告は運用メトリクス接続後の設定項目であり、実対戦開始の機能ブロッカーではない。

## 実機確認が必要になる境界

自動検証では、DB権限、状態遷移、競合、表示用データ、ビルド、単一ブラウザの操作まで確認する。次だけは最終的に利用者による実機確認が必要になる。

- 別アカウント2名が同時に同じカードを操作した時の体感
- スマートフォン2台での切断・復帰・バックグラウンド復帰
- 相手側に秘密情報が表示されず、確認操作だけが意図どおり共有されること
- 実ネットワーク遅延下の通知、楽観表示、再同期の見え方
