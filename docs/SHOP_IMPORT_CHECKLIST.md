# 店舗チェーン一括登録・棚卸し手順

店舗の「登録忘れ」と「登録済みだが検索上限で見えない状態」を分けて検出するための標準手順です。

## 対象範囲を先に固定する

作業開始前に、次を明記します。

- 実店舗だけか、通販を含むか
- TCG取扱店だけか、チェーンの全実店舗か
- 営業中、移転済み、閉店のどれを登録するか
- 基準日と、確認した公式一覧URL

営業中の実店舗は店舗マニフェストの `stores` に含めます。通販、移転済み、閉店は現行実店舗と混ぜず、DBの `operational_status` で区別します。

## 店舗マニフェストを作る

`data/shop-manifests/` にチェーンごとのJSONを置きます。必須項目は次のとおりです。

- `chainName`
- `sourceUrl`
- `verifiedAt`
- `scope`
- 店舗ごとの `sourceStoreId`、店舗名、都道府県、市区町村、住所、営業状態

`sourceStoreId` はチェーン内で変わらない識別子にします。店舗名だけを識別子にしないでください。

## 登録・更新

1. 最新の公式一覧からマニフェストを更新する。
2. 既存DBと `chain_name + source_store_id` で照合する。
3. 未登録は追加し、既存店舗は差分を確認して情報を補完する。
4. 移転・閉店店舗は削除せず `operational_status` を変更する。
5. 移転先がある場合は `superseded_by_shop_id` を設定する。
6. 適用済みマイグレーションは編集せず、新規マイグレーションを作る。

## 必須検査

ローカルの環境変数を設定した端末で実行します。秘密情報は出力・コミットしません。

```powershell
npm run audit:shops -- --manifest data/shop-manifests/yellow-submarine.json
```

次がすべて0件でなければ登録完了にしません。

- `missing`
- `unexpected`
- `duplicateDatabaseIds`
- `fieldMismatches`
- `incomplete`

さらに、価格登録画面でチェーン名を検索し、「さらに表示」を最後まで押して総件数と一致すること、各店舗名の個別検索で対象店舗を選択できることを確認します。

## 定期棚卸し

月1回、または店舗の開閉・移転告知が出た時に公式一覧とマニフェストを再比較します。自動スクレイピングは各サイトの利用条件を確認せず導入しません。

確認日だけを更新せず、必ず公式件数、店舗名、所在地、営業状態の差分を確認してください。
