# 価格修正申請の運用

誤った価格記録を履歴から直接書き換えず、申請と管理者レビューを通して修正版を作成するための運用手順です。

## 仕組み

- 登録PINの有効なセッションを持つ利用者だけが、カード詳細画面の価格記録から修正を申請できる。
- 同じ元記録に対する保留中の申請は1件だけ受け付ける。
- 申請時点では元の価格記録を変更しない。
- 管理者が承認すると、元記録へ `deleted_at` を設定して論理削除し、修正値を持つ新しい価格記録を作成する。
- 管理者が却下した場合、元の価格記録は変更しない。
- 申請理由、レビュー結果、レビュー注記、処理日時、監査用の利用者IDを保持する。

## 申請する

1. 登録PINのセッションが有効な状態でカード詳細画面を開く。
2. 修正対象の価格記録にある「この記録の修正を申請」を開く。
3. 販売価格、買取価格、確認日、在庫状況、メモを修正する。
4. 修正理由を入力して送信する。

価格は販売価格または買取価格の少なくとも一方が必要です。PIN、PINセッショントークン、秘密鍵などを修正理由やメモへ入力しないでください。

## 管理者がレビューする

1. Supabase AuthのMagic Linkで `/admin` へログインする。
2. 「価格修正申請」に表示される元記録、修正案、理由を確認する。
3. 必要に応じて店舗や登録内容を別経路で確認する。
4. レビュー注記を入力し、「承認」または「却下」を選ぶ。

承認後は元記録と修正版の監査関係を維持します。元記録を物理削除したり、適用済みマイグレーションを書き換えたりしないでください。

## 本番確認の原則

- テスト目的で架空の価格記録や修正申請を本番へ作成しない。
- 実在する誤記録が発生した時に、申請から承認または却下までを確認する。
- 管理操作に失敗した場合は連続操作せず、申請状態と管理者権限を確認する。
- DB変更が必要な場合は新しいマイグレーションを追加し、RLS、権限、Security Advisor、型生成を再確認する。
